REQUIREMENTS (high priority):

1) PAGE DISCOVERY (find the correct pages even if named differently)

2) RENDER & CAPTURE (use Puppeteer/Playwright if available)

  - screenshots (base64 or file path)
  - network calls made while rendering (to find remote policy fragments)
  - cookies set during load and on consent interactions
- If Puppeteer unavailable, fall back to fetch + lightweight JS rendering but mark "js_render: false" in output.

3) STRUCTURED EXTRACTION (parse the policy and terms into sections)
- Break the document into logical sections by headers. For each section extract:
  - section_title
  - section_text (first 500–2000 chars)
  - keywords found (list)
- Map sections to PDPL concepts using deterministic rules (no ML hallucination). Example mappings:
  - "lawful_basis", "processing_purpose", "data_retention", "data_subject_rights", "third_party_sharing", "data_transfer", "security_measures", "contact_details", "cookies", "children_data"
- Use regex + keyword lists in both Arabic and English to classify (provide lists below).

4) ALTERNATIVE NAMES HANDLING
- If page title or URL suggests replacement/refund policy or other retail policy, still parse it and search for standard Terms or Privacy content inside it (they sometimes bundle multiple policies). Do not discard.
- If a page contains only "Return Policy" but includes sections like "data collected" or "contact", include it as partial Terms/Privacy and mark which PDPL items are present vs missing.

5) COOKIE BANNER ANALYSIS
- Detect cookie banner presence visually (DOM) and by scripts.
- Evaluate functionality:
  - Is banner blocking trackers before consent? (Detect initial network calls to trackers before any click)
  - Are categories listed (necessary/analytics/marketing)?
  - Is there an "Accept/Reject" granular option?
  - Does the banner set cookies prior to consent? (Check cookie set timestamps vs user interaction)
- If the banner is not visible by default, simulate a scroll and look for delayed banners.
